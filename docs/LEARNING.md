# 三个实验怎么学、怎么复现、怎么讲

建议顺序为 P2 → P1 → P4。每次先跑一个小实验，解释一段真实数据，再读产生它的代码。这里的数字均来自离线仿真或主机程序；板端测量另行记录。

## 第一遍：认识仓库，不急着改参数

1. 打开 [系统框图](SYSTEMS.md)，画出三个项目中“输入 → 状态 → 输出”的路径。
2. 打开 [结果索引](RESULTS.md)，任选一行，从文字结果找到原始 CSV、脚本和参数。
3. 在仓库根目录运行 `python -X utf8 scripts/check_offline.py --only p2`。本机使用 `E:\python.exe` 替代 `python`，因为 PATH 中的 Python 入口不完整。结果写入新建的 `.runs/`，不会覆盖已提交证据。
4. 阅读新产生的 `summary.json` 和相应日志。退出码为 0 只说明该项检查通过；是否经过目标器件编译、硬件测试，要看检查的实际命令。

参考设计、独立实现、运行证据分别找：各项目 `SOURCES.md` 或 README、`rtl/ps/simulation/host_c` 等代码目录、`results*/evidence/verification`。厂商代码保留原有版权，自建教学模型不能称为厂商原工程。

## P2：先看一个字如何到达接收端

第一课只看 `TDATA/TVALID/TREADY/TLAST`。双方在时钟沿同时满足 `TVALID && TREADY` 才传走一个字；`TVALID=1,TREADY=0` 时，当前数据和边界标记必须保持。序号应随成功传输递增，不能每拍无条件递增。

执行路径：

1. [`axis_pattern_source.v`](../experiments/p2-zcu104-daq/rtl/axis_pattern_source.v) 产生 32 位测试字，高 16 位为帧号，低 16 位为帧内索引。默认 7 字一帧，最后一个字带 `TLAST`。
2. [`axis_sync_fifo.v`](../experiments/p2-zcu104-daq/rtl/axis_sync_fifo.v) 保存数据及边界标记，满时通过 ready 施加背压。深度为 3 的情况专门覆盖非 2 的幂地址回绕。
3. [`daq_axi_lite.v`](../experiments/p2-zcu104-daq/rtl/daq_axi_lite.v) 负责启停、显式重启和统计。STOP 在完整帧边界生效，写响应完成不等于数据通路已经停止；详见 [寄存器表](../experiments/p2-zcu104-daq/rtl/daq_axi_lite.md)。
4. [`frame_validator.c`](../experiments/p2-zcu104-daq/ps/frame_validator.c) 解读真正由 RTL 仿真写出的字节流，检查帧号和索引。它验证测试图样，当前不是通用数据 CRC。
5. [`simple_s2mm.c`](../experiments/p2-zcu104-daq/ps/simple_s2mm.c) 管理一个 28 字节包的接收、完成、错误锁存和显式恢复。理解 `for_device → submit → poll → for_cpu → validate` 的次序，比先背驱动 API 更有用。
6. [`daq_queue.c`](../experiments/p2-zcu104-daq/ps/daq_queue.c) 把已完成、已同步、已校验的包复制到 CPU 环形队列，再交给消费者。它仍使用一个固定 DMA 工作缓冲区，不是 DMA 描述符环或零复制。

先回答：若 DMA 报错和完成同时出现，应信哪一个？当前实现优先处理错误，不能因为完成位亮了就把缓冲区交给 CPU。超时也不等于 DMA 停止，缓冲区必须保留到确认设备已静止。

第二课看三种 AXI：AXI4 用于可寻址的存储器传输；AXI4-Lite 用于少量配置寄存器；AXI4-Stream 传输无地址的数据流，包边界由协议字段表达。DMA 将数据流搬到 DDR，PS 通过驱动和缓存操作读取。当前 Icarus/GCC 联测中的 DMA 回调由主机测试控制，不能当成已经访问 ZCU104 的 DDR。

第三课看 [队列所有权](../experiments/p2-zcu104-daq/ps/daq_queue.md)：`dq_borrow` 借出队首的 const 指针，但该槽仍占容量；`dq_release` 后槽才能复用，旧指针随即失效。满队列返回 FULL，停止提交下一包，不覆盖旧包。此前有效包即使遇到后续接收错误也可继续消费，全部释放后才允许重启。这是单调用者协作式 API，不能直接当作多线程或 ISR 并发队列。

练习：在新的实验副本里把一帧长度从 7 改为 1，再解释 `TLAST` 应出现在哪些握手沿；只改 RTL 会让哪些接收长度和校验假设不一致？答案是每个成功传输都是帧尾，同时软件包长、验证器和 DMA 长度也要一致，不能只改一个参数。

性能课先分清时间边界。[主机测量程序](../experiments/p2-zcu104-daq/tests/bench_daq_queue.c) 的队列延迟从成功入队后到内容检查、成功释放后；首次终点遗漏后两步，旧证据保留。新增 [9 组 CPU/墙钟测量](../experiments/p2-zcu104-daq/results/performance_cpu/host_measurements.csv) 显示零等待接近一个核，消费等待降低进程 CPU 时间占比。比值为进程 CPU 时间/同段墙钟时间，未按核数归一化，不是全机或 A53 使用率；略高于 100% 的原值与未查明原因均保留，不据小差值排名。

比较容量 1、3、8：更深队列容纳积压，本次主要增加排队延迟，不会让慢消费者更快。再读 [RTL 三时刻测量](../experiments/p2-zcu104-daq/rtl/fifo_latency.md)：首次 VALID、入口握手、出口握手分别界定源等待和 FIFO 驻留；6 组轨迹逐周期核对“接受=输出+复位丢弃+待输出”。RTL 时钟与主机墙钟不混用，也不是 ADC 到消费端延迟；可停顿源的等待不是丢样，10 ns 仿真时钟不证明板端达到 100 MHz，CPU 队列高水位也不是 RTL FIFO 占用。

## P1：从电感状态走到一次控制更新

先画 Buck 的开关节点、电感、电容和负载。理想连续导通、稳态、损耗忽略时，电感平均电压为零，因此 `Vout ≈ D × Vin`。本教学电路 `Vin=9 V`、目标 `2 V`，固定占空比约为 `2/9`。这条关系不说明启动瞬态，也不适用于所有断续导通或受限工况。

[`SWITCHING.md`](../experiments/p1-c2000-buck/simulation/SWITCHING.md) 定义实际 PWM 开关求解。开通时电感电压约为 `Vin−Vout`，关断等效低侧导通时约为 `−Vout`；电感电流连续，电容电压也连续。先用 `di/dt = vL/L` 算电流斜率，再对照 CSV。电容滤波后，理想三角电流近似给出 `ΔV ≈ ΔI/(8 fs C)`，实际器件还要考虑 ESR 等损耗。

控制执行路径：测量与码箱界限 → 判定故障 → 检查显式清除证据 → 软启动参考 → PI → 占空比限制 → 下一周期功率级。对照 [`buck_control.c`](../experiments/p1-c2000-buck/host_c/buck_control.c) 的 `buck_controller_step_observed()` 和 `buck_voltage_pi_step()`；[`BuckClearEvidence`](../experiments/p1-c2000-buck/host_c/buck_control.h) 表示可观测性及绝对值上界。旧标量入口仅保留理想精确测量语义。

PI 的比例项即时响应误差，积分项积累持续误差。增大增益可能缩短部分响应，也可能增加超调或饱和后的恢复负担。查看 [9 组增益比较](../experiments/p1-c2000-buck/simulation/PI_COMPARISON.md)：没有“所有指标同时最好”的候选，默认参数仍保留。

软启动逐步升高参考值。过流/过压/欠压锁存首个故障，故障消失不自动恢复；当前量化路径还要求完整有效测量区间在原 0.1 V/0.1 A 清除界内。端点码信息不足就继续锁存，固定等待不能补足证据。阈值和理想码箱仍是教学假设，不能当作未知板卡的保护额定值。

重点看 [PWM 保护记录](../experiments/p1-c2000-buck/simulation/PROTECTED_SWITCHING.md)：模型中的 duty=0 表示理想低侧持续导通，仍允许反向电流与负电压，不能等同真实驱动器“两管关闭”。电流、电容储能不会在软件故障位翻转时消失。

练习：把负载由 4 Ω 变为 2 Ω 的瞬间，先不看图，判断负载电流、电感电流、电容电流和输出电压如何变化。答案：负载所需电流立即增加，电感电流不能跳变，差额先由电容供应，所以输出电压开始下降；控制器随后增加输入能量。

ADC 与 PWM 同步的目的，是让测量时刻可解释并避开不合适的开关噪声位置。现在可继续读 [`target_main.c`](../experiments/p1-c2000-buck/firmware/target_main.c)：ePWM1 SOCA → ADCA 三个 SOC 依次转换 → EOC2 中断 → 标度换算 → 原控制器 → CMPA 影子值。独立工程已由 TI cl2000 真实编译、链接为 C28x EABI ELF，见 [目标构建说明](../experiments/p1-c2000-buck/firmware/README.md)。GPIO 未复用成 PWM，启动 OST 一直锁存，没有输出启用路径；构建成功不等于目标执行成功，也未证明 ISR 在 20 µs 内完成。

再沿 [`c_controller.py`](../experiments/p1-c2000-buck/host_c/c_controller.py) → [`io_timing_buck.py`](../experiments/p1-c2000-buck/simulation/io_timing_buck.py) 读实际反馈路径：本轨迹末态 → ADC 量化/码箱 → C 核心 → PWM 量化/一周期队列 → 功率级，Trip 本拍覆盖为零。[修复后的六场景闭环](../experiments/p1-c2000-buck/host_c/CLEAR_MEASUREMENTS.md) 实际调用 C 36,006 次，与独立 Python 一致；短接管试验禁止 Python 更新，仅改测试 C 初态就改变脉冲和 L/C 状态。闭环 ADC 仍在 Python，C ADC 换算另有主机执行测试；目标 ADC/ISR 未执行。仍假定同时采样、计算无延迟；采样超调小于 10% 也不代表周期内峰值达标。

两个旧反例是负压约 −1.9 V 被截为 0 V，以及真实 0.104541 A 被解码为 0.096680 A。历史标量判据的副本曾接受请求，旧主轨迹在 80 ms 恢复。当前分别因不可观测、码箱上界约 0.104736 A 超界而拒绝；三个量化故障在 80 ms 也都因零码继续锁存，有效内码则可显式清除。16 项 Python 测试及 C 码箱测试通过，但尚未补足真实前端信息，不能称硬件安全恢复已完成。

## P4：先理解功率方向，再理解 ZVS

两个桥输出高频方波，电感承受两桥折算电压之差。相位不同会改变电感电流与桥电压的乘积，因此改变平均传输功率及方向。变比定义为 `n=N1/N2`，第二侧折算到第一侧的电压是 `nV2`；电流和电感的折算不能混用。

从 [`MODEL.md`](../experiments/p4-dab/MODEL.md) 的分段积分推导读起。理想 SPS、50% 方波、选择零直流偏置周期解时：

`P = n V1 V2 / (2π fs L) × φ × (1 − |φ|/π)`，其中 φ 用弧度。代码接口的角度单位是度。默认 `24 V/12 V、n=2、20 kHz、100 μH` 下，`φ=+30°` 对应 `+20 W`，`−30°` 对应反向 `−20 W`。这些是独立低压教学参数。

执行路径：

1. [`dab_sps.py`](../experiments/p4-dab/dab_sps.py) 按开关事件分段积分，再选择零偏置的周期轨道；它不是启动过程。
2. [`dab_transient.py`](../experiments/p4-dab/dab_transient.py) 增加串联电阻，保留跨周期电流，处理相移斜坡、采样保护和显式清除。
3. [`dab_power_loop.py`](../experiments/p4-dab/dab_power_loop.py) 是原 RL 功率闭环，用刚完成周期的功率反馈；相移有幅度和变化速率限制，条件积分也考虑这些限制。
4. [EPS 比较](../experiments/p4-dab/EPS.md) 在第一桥引入零电压区间。比较时必须匹配电压、频率、电感和传输功率；不能靠少传功率来宣称 RMS 更低。
5. [`dab_continuous.py`](../experiments/p4-dab/dab_continuous.py) 将死区、开通和非死区串成整周期，传递真实电流，分别记录电阻、二极管及开通电容电荷重分配。
6. [`dab_loss_budget.py`](../experiments/p4-dab/dab_loss_budget.py) 在连续模型上匹配接收端功率，再计算明确器件条件下的部分损耗预算。
7. [`dab_continuous_control.py`](../experiments/p4-dab/dab_continuous_control.py) 将原 PI 和保护接到持久 RLC/Coss 状态；固定主桥时钟，只用上一周期实算 P2 安排未来开关沿。

ZVS 是开通前器件电压已接近零，不是电流符号正确就自动成立。早期 [极性检查](../experiments/p4-dab/COMMUTATION.md) 只给必要条件；现在接着读 [`dab_deadtime.py`](../experiments/p4-dab/dab_deadtime.py)，看共享电感电流如何同时推动节点电容，并触发二极管钳位。模型用 Qoss/30 V 得到线性电荷等效电容，不能把它当成真实非线性 Coss 或 Eoss 曲线。

[局部死区阶段](../experiments/p4-dab/DEADTIME.md) 比较 24 组独立窗口，并完成六个独立 ngspice 网表的 [轨迹对照](../experiments/p4-dab/results_deadtime_spice/RESULTS.md)。后续 [连续整周期模型](../experiments/p4-dab/CONTINUOUS.md) 已把实际末态传给下一事件，不再用理想边沿电流重新初始化。局部曾得到 8/8 到轨的 +2.7 W、500 ns EPS 工况，连续模型中变成 6/8；判断必须基于对应模型的真实轨迹。ngspice 记录仍只覆盖局部窗口，不能冒充整周期 SPICE 验证。

固定角阶段的 [实际接收功率匹配](../experiments/p4-dab/results_loss_budget/RESULTS.md) 中，正向接收量为 P2，反向为 −P1，不能都拿 P2 的绝对值比较。指定相移区间内 10 点有 9 点匹配成功，另 1 点不能外推为全局不可达；该阶段 47 项测试及 9 份完整波形回读通过，EPS 内部角度未重新优化。

一个值得讲清的反例是 13.5 W 正向、150 ns 死区：EPS 的 RMS 电流略低，模型 ZVS 数量也更多，但典型参数下部分损耗为 **0.468141 W**，高于 SPS 的 **0.431168 W**，其中开通电容重分配项更大。因此 ZVS 数量和 RMS 都不能单独代表总损耗；要在同接收功率下逐项记账，也不能把残余单管电容能量再次叠加。

再看 [连续物理闭环](../experiments/p4-dab/CONTINUOUS_CONTROL.md)：55 项测试与 6 份波形回读通过，覆盖阶跃、换向、饱和返回和显式恢复。采样 Trip 取消待开通高管，经真实死区转为两桥低低续流，保留电流和节点电压。1.6 A 过流实验的峰值仍达约 1.655 A，阈值不是瞬时钳位；100 W 请求只得到约 31.079 W，饱和不算达标。当前只闭环 SPS；检测电压故障是输入注入，物理母线仍为固定理想电源。

练习：电压匹配、相移为零时，零偏置理想模型没有交流电流；电压不匹配时为什么仍可能有电流而平均功率为零？因为正负半周电感电压不为零，产生往返储能和环流；平均有功为零不等于 RMS 电流为零。

对效率的正确问题是：损耗模型计入了哪些器件、哪个温度和开关条件？当前沟道与栅驱项是 25°C、10 V 驱动参数的后处理，未反馈到连续模型；功率匹配也没有因此重新求解。重叠开关、反向恢复、磁芯及温度反馈等仍未计入，所以这是部分损耗预算，不是整机效率或实测效率，更不是 RD264 原厂性能。

## 用实际失败讲定位过程

| 问题 | 看哪份证据 | 要讲清的因果关系 |
| --- | --- | --- |
| Buck 首次 PI 启动不达要求 | [首次失败](../experiments/p1-c2000-buck/evidence/simulation-attempt1/)、[后续比较](../experiments/p1-c2000-buck/simulation/PI_COMPARISON.md) | 保留失败输入和判据，分析启动/扰动指标，再在隔离副本调整增益；没有把条件改松来“通过” |
| P2 主机联测启动失败 | [运行失败日志](../experiments/p2-zcu104-daq/results/frame_validator/runner_failure.log) | 首先定位 WSL 路径传递，区别工具启动失败与数据通路错误；修正调用后实际跑 RTL 数据和 C 校验 |
| P2 延迟统计终点取早 | [修复说明与前后证据](../experiments/p2-zcu104-daq/ps/daq_queue.md) | 计时终点原先在内容检查、释放之前；先保留旧结果，再把终点移至成功释放之后，复跑 9 组主机测量 |
| Buck 单极性与量化清除盲区 | [反例及测量区间修复](../experiments/p1-c2000-buck/host_c/CLEAR_MEASUREMENTS.md) | 只从原码和声明标度形成有效区间，拒绝不可观测或跨界码箱；不读理想真值、不靠等待、阈值不变 |
| DAB 清除后再次过流 | [诊断记录](../experiments/p4-dab/diagnostics/transient_failure_01/README.md) | 剩余电流与过快反向指令共同作用；保留原阈值及再次跳闸测试，演示更缓慢的恢复指令 |

讲问题时按“现象 → 证据 → 原因 → 最小修改 → 同条件复验”展开。不要只说“调了一下参数就好了”。

## 面试问题与回答要点

| 问题 | 回答要点 |
| --- | --- |
| PS 与 PL 为什么分工？ | PL 处理并行、确定时序的数据通路；PS 负责配置、缓冲管理和上层处理；明确两者接口 |
| FIFO 满了怎么办？ | 当前源支持背压，暂停发送并保持当前拍；不能据此断言真实不可暂停 ADC 也不会丢数据 |
| 为什么 DMA 后 CPU 仍会读到旧数据？ | 缓存副本与设备访问内存不一致；说明平台缓存 API、整块隔离缓冲区和所有权交接，而不是只说 volatile |
| 轮询与中断有什么区别？ | 轮询主动查状态，中断由设备通知；两者都要正确处理错误、超时和缓冲所有权。当前离线流程以有界轮询为主 |
| 如何排查丢帧？ | 顺着源端序号、FIFO/握手、DMA 状态与长度、缓存同步、解析器逐层检查；先定义统计窗口和期望帧数 |
| 为什么不把测试字直接写进 C 用例？ | 正常路径读取 RTL 实际输出，避免两个独立假数据自洽；故障路径才有针对性地修改输入 |
| 环形队列借出后为什么仍算占用？ | 消费者还在使用该槽，生产者不能覆盖；释放后指针失效。队列深度只能容纳积压，不能提高消费者处理能力 |
| 电感、电容越大越好吗？ | 较大值往往减小纹波，但影响体积、成本、动态响应和控制设计；结合实际参数比较，不能单看一项 |
| 电压模式与峰值电流模式不同在哪里？ | 前者由电压环调制占空比，后者包含逐周期电流控制环节；当前实现不声称已完成峰值电流模式 |
| 软件过流能代替硬件保护吗？ | 采样和关断都有延迟；P4 连续模型的 1.6 A 阈值仍出现约 1.655 A 峰值。阈值不是电流钳位，离线判据也不能证明硬件 Trip 延迟 |
| 主机 C 闭环、目标编译成功就能驱动开发板吗？ | 主机 C 闭环和 C ADC 换算已测，目标 ELF 已链接；目标 ADC/ISR 未执行，GPIO 未接 PWM、OST 未解除，目标时序仍未验证 |
| ADC 读到零为什么不一定安全？ | 单极性输入可能隐藏负压；当前零码拒绝清除，即使等到 80 ms 也不放行。有效内码必须整个区间满足原界限，保守拒绝不能替代硬件测量证据 |
| 为什么会有积分饱和？ | 执行量受限时误差仍积累，解除限制后恢复缓慢；指出当前条件积分如何对应执行器限制 |
| DAB 为什么能反向传输？ | 两侧都是有源桥，反转相位关系可改变平均功率方向；必须统一端口功率正方向 |
| 为什么同功率 EPS 可能降低 RMS？ | 零电压区间可以减少不传递有效功率的电流，但收益依赖电压比和负载；无改善点也应保留 |
| 电流极性正确为什么还不能确认 ZVS？ | 电荷与时间预算可能不足，有限死区结束时仍有剩余器件电压；要看动态节点解 |
| ZVS 更多、RMS 更低就一定损耗更小吗？ | 本项目同接收 13.5 W 时 EPS 恰好给出反例；逐项比较开通电荷重分配、导通和驱动等预算，不能只数 ZVS 事件 |
| 部分损耗估算为什么不是整机效率？ | 沟道/栅驱后处理未反馈功率匹配，重叠开关、反向恢复、磁性件和温度反馈等未完整建模；也没有实物测量 |
| 这些项目哪些来自厂商？ | 原始资料、驱动来源和许可证见各项目来源记录；RTL/教学模型/控制扩展按文件和 Git 历史逐项说明 |

## 两分钟项目讲解稿

**P2：** 我以 ZCU104 PS-PL 架构为目标，实现数据发生器、FIFO、AXI-Lite 控制及有界 CPU 接收队列，把真实 RTL 输出交给 C 校验。借用期间保留槽所有权，满时不覆盖；主机测量区分墙钟和进程 CPU，慢消费者下更深队列主要增加等待。RTL 另记录首次呈现、入口和出口握手，核对复位丢弃及守恒。两种时钟不混用，进程 CPU 不是板端 A53 使用率；完整 Vivado、真实 DDR/cache 和板端性能仍未验证。

**P1：** 我参考 TI 数字 Buck 资料，建立 PWM 模型及 PI、软启动、三类保护。发现量化清除盲区后，仅按原码构造可观测标记和完整码箱界限，保留原阈值；零码的 80 ms 请求继续锁存，有效内码可显式清除。修复后 36,006 次 C 闭环调用与 Python 一致，短试验证明 C 接管，C ADC 换算也已在主机执行。F280049C 新接口编译链接通过且始终禁止输出；目标 ADC/ISR 未执行，前端信息缺口仍需实测。

**P4：** 我参考 Toshiba DAB 资料，从 SPS/EPS 推进到连续死区物理模型，再把功率 PI 和采样保护接入持久状态，完成阶跃、换向、饱和与恢复的 55 项测试。1.6 A 阈值仍出现约 1.655 A 峰值，不能称瞬时限流。固定角接收功率匹配完成指定区间 9/10 点；13.5 W 时 EPS 虽然 RMS 更低、ZVS 更多，部分损耗却更高。ngspice 只验证局部换流，后处理损耗未反馈，也不是整机效率或原厂性能。
